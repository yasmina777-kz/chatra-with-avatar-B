# Chatra Backend

FastAPI + SQLAlchemy бэкенд для образовательной платформы Chatra.

## Запуск

Выполняйте команды из корня репозитория, где находятся `main.py` и `requirements.txt`.

### 1. Создать виртуальное окружение и установить зависимости

```bash
python3 -m venv venv
source venv/bin/activate        # macOS / Linux
# venv\Scripts\activate         # Windows

pip install -r requirements.txt
```

### 2. Создать файл `.env`

```bash
cp .env.example .env
```

В шаблоне активен PostgreSQL. Для локального запуска без отдельного сервера БД
замените строку `DATABASE_URL` на SQLite (не оставляйте две активные строки).
Настройте значения в `.env`:

```env
OPENAI_API_KEY=sk-proj-...       # ключ с platform.openai.com/api-keys
SECRET_KEY=минимум-32-случайных-символа
DATABASE_URL=sqlite:///./chatra.db   # или postgresql://user:pass@host/db
APP_BASE_URL=http://localhost:8000
```

### 3. Запустить сервер

```bash
source venv/bin/activate
uvicorn main:app --reload --reload-exclude venv --host 0.0.0.0 --port 8000
```

Проверка ответа сервера в отдельном терминале:

```bash
curl --fail http://localhost:8000/health
```

Ожидаемый ответ: `{"status":"ok"}`. Этот маршрут проверяет доступность HTTP-сервера;
он не проверяет базу данных и внешние AI-сервисы.

Swagger UI: [http://localhost:8000/docs](http://localhost:8000/docs)  
Health check: [http://localhost:8000/health](http://localhost:8000/health)

## Проверка регистрации

После установки зависимостей запустите из корня репозитория:

```bash
python -m unittest discover -s tests -v
```

Тесты обращаются к настоящему маршруту `/auth/register` через FastAPI TestClient
и используют отдельную SQLite-базу в памяти. Рабочая база и внешние AI-сервисы
не нужны. Проверяются допустимые роли `student` и `teacher`, отказ для `admin`
и неизвестных ролей, обязательность поля роли и повторная регистрация.
Создание пользователей через защищённый `/admin/users` использует отдельную схему.

## База данных

По умолчанию используется SQLite (`chatra.db` в корне проекта) — таблицы создаются автоматически при первом запуске.

Для PostgreSQL укажите `DATABASE_URL=postgresql://user:pass@host/db`. Схемы `university` и `school` создадутся автоматически.

В каталоге `migrations/` находятся SQL-скрипты для PostgreSQL; конфигурации
Alembic в репозитории нет, поэтому команда `alembic upgrade head` здесь не применяется.
Автоматическое создание таблиц не обновляет структуру уже существующих таблиц.
Перед применением SQL-скриптов проверьте текущую схему и требования в комментариях
к выбранному файлу: например, `002_rag_pgvector.sql` требует расширения pgvector.

## Переменные окружения

| Переменная | Описание | По умолчанию |
|---|---|---|
| `OPENAI_API_KEY` | **Обязательно для AI функций** | — |
| `SECRET_KEY` | Секрет для подписи JWT | небезопасный дефолт |
| `DATABASE_URL` | SQLAlchemy строка подключения | `sqlite:///./chatra.db` |
| `APP_BASE_URL` | Базовый URL для ссылок на файлы | `http://localhost:8000` |
| `UPLOAD_DIR` | Папка для загружаемых файлов | `uploads` |
| `CORS_ORIGINS` | Разрешённые origins через запятую, или `*` | `*` |
| `ELEVENLABS_API_KEY` | Клонирование голоса учителя + озвучка лекций аватара (см. раздел "AI-аватар" ниже) | не задан → озвучка недоступна |
| `DID_API_KEY` | Видео-интро аватара (говорящее фото, 15-30 сек на лекцию) | не задан → видео-интро пропускается, остаётся фото+аудио |

## AI-аватар преподавателя

Учитель один раз создаёт своего аватара (фото + образец голоса), затем по
материалам, закреплённым за классом, может создавать лекции — аватар
озвучивает презентацию слайд за слайдом голосом учителя и в конце
формирует конспект.

**Создание аватара и каждая новая лекция требуют одобрения администратора**
в разделе `/admin/avatars` и `/admin/avatar-lectures` — это сознательное
ограничение, так как голос и видео генерируются через платные сторонние API
(ElevenLabs и D-ID) и могут быть дорогими при бесконтрольном использовании.

Без ключей `ELEVENLABS_API_KEY` / `DID_API_KEY` система продолжает работать:
заявки на аватар можно одобрять, лекции — создавать, но озвучка/видео не
генерируются, пока администратор не добавит ключи в `.env`. Текст лекции и
конспект всегда генерируются через уже настроенный `OPENAI_API_KEY`.

Видео-аватар генерируется **только для первого слайда лекции** (короткое
говорящее интро ~15-30 сек) — полное видео на каждую минуту лекции
обходится в разы дороже и не предусмотрено намеренно. Основная часть
лекции — это слайд + статичное фото учителя + аудио, синхронно листающиеся
в плеере на фронтенде.

## AI оценивание

Модель задаётся константой `OPENAI_MODEL` отдельно для каждого обработчика:
`services/ai_grader.py` использует `gpt-4o`, а `routers/ai.py` — `gpt-4o-mini`.

## Структура проекта

```
main.py          — точка входа, FastAPI app
models.py        — SQLAlchemy модели
schemas.py       — Pydantic схемы
db.py            — настройка базы данных
deps.py          — зависимости (get_db, get_current_user)
security.py      — JWT утилиты
routers/         — эндпоинты (auth, users, classes, ai, ...)
crud/            — операции с БД
services/        — бизнес-логика (ai_grader, deadline_checker, ...)
parsers/         — парсинг файлов (PDF, DOCX, OCR)
websocket.py     — WebSocket чат
migrations/      — SQL-скрипты для PostgreSQL
uploads/         — загруженные файлы
```
